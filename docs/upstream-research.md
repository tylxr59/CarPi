# Upstream research and reuse decision

Reviewed 2026-09-23. GitHub repositories were inspected as shallow checkouts, including their root license files where present. This repository contains **new Python code only**; no upstream source, traces, binaries, PDFs, certificates or keys were copied. A top-level license does not establish ownership of every embedded third-party file, so bundled material is treated separately.

Other public projects frequently called “CarPlay for Raspberry Pi” receive an iPhone stream on the Pi. Their receiver-side AirPlay handshake, H.264 decoding and touch forwarding can inform packet interpretation, but this project must send a stream **from the Pi to the Subaru**. The public [discussion of `_carplay-ctrl._tcp`](https://github.com/45clouds/WirelessCarPlay/issues/28) is a useful hypothesis for discovery; it is not a verified endpoint for this vehicle.

## Research gaps to close before importing protocol code

1. Check whether a **licensed**, maintained sender library actually supports CarPlay receiver requirements, not generic Apple TV mirroring alone.
2. Collect a legally shareable, sanitized trace of this vehicle's phone-source exchange, then distinguish CarPlay-specific RTSP/HTTP, mDNS and iAP2 continuations from generic AirPlay.
3. Review licensing at file/dependency level for any future code import. Keep Apple proprietary documentation, Xcode files, leaked PDFs, MFi private material and credentials out of Git.
