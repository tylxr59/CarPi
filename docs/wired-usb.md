# Wired USB operator workflow

This currently reaches **W1: development NCM gadget enumeration**. It is not an iPhone emulator and is not expected to start CarPlay on the Subaru. The Pi remains the intended phone/source; the vehicle is the USB host.

1. Power the Pi 4B independently through a suitable, electrically reviewed arrangement. Reserve its USB-C data lines for gadget mode. Do not join competing 5 V sources or backfeed the Pi; a USB-C splitter or GPIO power arrangement must be checked for isolation and current rating. Keep SSH on Ethernet/Wi-Fi.
2. On the Pi, `sudo carpi usb doctor`. If no UDC appears, use `sudo ./install.sh --enable-usb-gadget` from the checkout, then reboot. This option backs up `/boot/firmware/config.txt` and appends the smallest `dwc2,dr_mode=peripheral` overlay only when no UDC or existing dwc2 overlay is detected. The ordinary installer makes no boot edit. If ConfigFS is absent, run `sudo modprobe libcomposite` and, if `/sys/kernel/config` is not mounted, `sudo mount -t configfs configfs /sys/kernel/config`; rerun doctor. These are Pi-side commands, not development-host package instructions.
3. Run `sudo carpi usb setup` and answer `YES` to the independent-power prompt. For noninteractive use, `sudo carpi usb setup --separate-power`. It refuses non-Pi-4 models, missing/multiple UDCs, a UDC already owned by another gadget, or missing ConfigFS/NCM support. Binding happens last.
4. Inspect `sudo carpi usb status` and `sudo carpi usb net-status`. Status prints ConfigFS values and the UDC state; it cannot dump the exact controller-generated descriptor bytes. With a Linux **test computer** as host, run `lsusb -v -d 1d6b:0104` and save the device/configuration/interface/endpoint sections. Verify one NCM control/data function, its data altsetting and a stable replug. On macOS use System Information/`ioreg` for the equivalent USB tree. This is W1, not phone compatibility.
5. Start `sudo carpi usb trace` in one SSH terminal. It logs UDC state and NCM carrier changes. Optional `sudo carpi capture network` captures the gadget NCM interface to a local private file. `sudo carpi capture usb` uses `usbmon0` when available, but **usbmon on the Pi is host-side tracing and may not expose gadget EP0 traffic**. To see USB SETUP packets, capture on a Linux computer in the **host** role or use a hardware analyzer between Pi and Subaru. `sudo modprobe usbmon` then `sudo tcpdump -i usbmonN -s 96 -w capture.pcap` on that host. The vehicle lacks a Linux capture shell, so Pi-side state logs cannot prove absence of an Apple request.
6. After the PC test, connect the Pi USB-C **data** port to the Subaru USB host with a USB-C to USB-A data cable. Observe vehicle UI, UDC state and NCM. Do not interpret a silent vehicle as a completed compatibility test; a generic identity has no iPhone mux or Apple configuration reveal.
7. Disconnect the data cable. Run `sudo carpi usb teardown`; repeat to verify idempotence. This unbinds the UDC and removes only the `carpi` gadget. There is no USB autostart service.

Capture files are mode 0600 in a mode 0700 directory. They may contain device serials, MACs, Wi-Fi credentials, location and authentication material. Review locally before sharing. In Wireshark use `usb.setup`, `usb.bRequest == 0x52`, `usb.bRequest == 0x09` (SET_CONFIGURATION), `usb.bRequest == 0x0b` (SET_INTERFACE), or `ncm || ipv6`; filter syntax depends on Wireshark version. Network captures default to 256-byte snapshots and USB captures to 96-byte snapshots; these can still contain secrets.

To revert the optional boot change, restore the backup named by the installer, or remove only the appended `[all]`/`dtoverlay=dwc2,dr_mode=peripheral` lines if they are still the last two directives, then reboot. Do not remove someone else's existing overlay.
